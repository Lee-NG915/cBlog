# 读者与证据研究
先读 [运营上下文](../content-context.md)。区分两类证据：读者是否有这个问题，与技术判断是否成立；论坛提问只能支持前者，不能自动证明技术结论。

## 研究方法
从用户提供的材料和公开一手资料开始。官方文档核对定义、版本及条件；公开讨论提取任务、症状、已尝试方法。需要最新产品行为时重新核对官方文档。
记录每条证据的链接或本地路径、日期、原文短摘或明确标注的转述、能支持的结论、不能支持的结论。不可访问的材料标记未读取，不用标题推断正文。
按运营/开发及具体任务聚类，报告样本来源和独立样本数；同一转载不算多个独立来源。小样本只产生待验证假设，不推断全体读者或需求占比。
主动寻找反例、版本差异、替代解释。角色不明时保留未知，不根据头像或语气猜身份。

## 交付格式
问题 → 初步假设 → 支持证据 → 反证/限制 → 当前判断 → 缺口 → 下一步验证 → 可用于文章的案例/工具。
没有证据时输出最小验证方案，不能编造用户原话、测试截图和本人经历。访谈提纲可以准备；联系受访者需要相应授权。

## 来源与适配
本技能为 cBlog 项目适配版，不是上游原版安装。来源版本、分类及取舍见 [筛选报告](../../../docs/skill-selection-2026-09-23.md)。

## 成果同步收尾
本任务产出本地审阅通过的调研、梳理或交付文档及配套图片时，按 [cblog-notion-sync](../cblog-notion-sync/SKILL.md) 同步到 Notion并核验；未通过的草稿保持待审，不作为已通过成果同步。
