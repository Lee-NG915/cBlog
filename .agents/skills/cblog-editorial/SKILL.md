# 写作与主编审稿
先读 [运营上下文](../content-context.md)。使用用户已有简报和证据，不为每次写作重复进行定位访谈。

## 正文结构
一篇只解决一个问题，覆盖：具体场景、核心判断、证据、推理、操作与异常分支、可复用工具、适用边界。信息要求不等于七张图或七个标题。
- 排查教程：症状 → 前提 → 贯穿案例 → 检查顺序 → 正常/异常分支 → 清单。
- 方案比较：同一任务与条件 → 比较维度 → 各方证据 → 条件化选择。
- 实践复盘：基线 → 改动 → 验证方式 → 实际结果 → 其他解释 → 下一步。
没有结果就称方案或过程记录，不称增长实绩。

## 实操深度
关键步骤写清在哪里看、具体动作、预期观察、判断条件及异常后下一步。工具必须和案例配套；空表、术语罗列和“做好埋点”等口号不能单独通过审稿。
具体数字只能来自来源或明确标注的模拟示例；不能为了文案更具体填入虚构收益。只陈述用户真实承担的职责，不能把团队贡献自动改成个人主导。

## 审稿顺序
先检查证据与推理，再检查操作完整性，最后修改语言、结构与标题。保留作者语气，不机械添加焦虑、反转或夸大承诺。
任一关键主张无证据、关键操作不可执行、标题承诺未交付：退回，并列出所在段落、问题、修正动作和验收方式。编辑评分不是流量预测；“主编通过”不是用户授权发布。

## 交付
正文、标题候选（数量按需要）、来源清单、读者工具、审稿记录。图文另给逐页论点和所需证据。技术干货缺失时先补研究，不能以精美配图代替。

## 来源与适配
本技能为 cBlog 项目适配版，不是上游原版安装。来源版本、分类及取舍见 [筛选报告](../../../docs/skill-selection-2026-09-23.md)。

## 成果同步收尾
本任务产出本地审阅通过的调研、梳理或交付文档及配套图片时，按 [cblog-notion-sync](../cblog-notion-sync/SKILL.md) 同步到 Notion并核验；未通过的草稿保持待审，不作为已通过成果同步。
