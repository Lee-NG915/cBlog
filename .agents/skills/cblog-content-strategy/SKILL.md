# 内容策略
先读 [运营上下文](../content-context.md)，复用已有定位与用户约束。定位是待验证假设，不是已经证明的市场结论。

## 产物
把输入拆为原始想法、待调研问题、可立项文章。每个方向记录：读者、具体任务、可观察症状、已有证据、证据缺口、下一步验证、读者可带走的工具。
按读者相关性、证据可得性、操作收益、制作成本排序，说明理由。不要给缺少依据的维度虚构精确分数、搜索量或商业价值。
博客侧考虑可检索问题和内部链接，小红书侧考虑封面是否让目标读者识别场景；不把博客 SEO 当成小红书推荐算法。

## 交接
想法 → 调研 → 可立项 → 写作 → 审稿 → 制图 → 发布复盘。调研必须得到一个有条件的核心判断和可验证案例，才能立项。证据不足时交付研究任务，不包装成完整文章。
用户要求写入 Notion 时，先读实际库结构再更新已有记录，保留关联和用户修改。没有连接权限时交付本地稿，说明未同步。发布和外联不由选题任务自动授权。

## 输出
给出优先选题、选择理由、暂缓原因、最小调研行动及交付物。只有用户要求排期时才拟定日历，不自动创建定时任务。

## 来源与适配
本技能为 cBlog 项目适配版，不是上游原版安装。来源版本、分类及取舍见 [筛选报告](../../../docs/skill-selection-2026-09-23.md)。

## 成果同步收尾
本任务产出本地审阅通过的调研、梳理或交付文档及配套图片时，按 [cblog-notion-sync](../cblog-notion-sync/SKILL.md) 同步到 Notion并核验；未通过的草稿保持待审，不作为已通过成果同步。
