# cBlog SEO 审查
按用户范围读取实际页面、Next配置和构建方式；先核对 package.json。源码主要在 apps/web，品牌文件在 apps/web/lib/brand.ts 与 docs/brand-core.md。

## 检查顺序
抓取与索引前提 → 状态码/重定向 → robots与sitemap → canonical → 标题与摘要 → 语义结构 → 内链 → 图片和性能 → 内容是否回答目标问题。
区分源码、渲染结果、真实线上响应和搜索后台索引状态。源码存在不证明线上正确；没有 Search Console 不能声称已索引或流量提升。
JSON-LD需检查实际脚本或渲染DOM；文本抓取未显示脚本不能据此报告缺失。标题长度等经验值用于可读性判断，不当作固定排名规则；实时规则用搜索引擎官方文档核对。

## 交付与修复
每项给出页面/文件位置、复现证据、影响范围、修复建议与验收方法，优先解决可证明的问题。用户请求修复时完成范围内改动及相应检查；仅审查时交付报告。
不批量生成薄内容、不自动改站点URL结构、不把所有草稿公开。涉及视觉时复用已有 style-optimization，不引入新品牌系统。

## 来源与适配
本技能为 cBlog 项目适配版，不是上游原版安装。来源版本、分类及取舍见 [筛选报告](../../../docs/skill-selection-2026-09-23.md)。

## 成果同步收尾
本任务产出本地审阅通过的调研、梳理或交付文档及配套图片时，按 [cblog-notion-sync](../cblog-notion-sync/SKILL.md) 同步到 Notion并核验；未通过的草稿保持待审，不作为已通过成果同步。
