# 内容运营上下文

当前场景：cBlog 博客、笔记应用与小红书图文运营；职业方向是从独立站工程走向出海产品商业化。
定位工作假设：面向已在做 Shopify 独立站的运营和开发，解释页面、数据与转化的具体问题，交付能执行的排查方法。三条主线为数据与埋点、页面与商品决策、性能与协作。
用户已明确反馈“干货不足”。优先补真实证据、完整案例、异常分支和可复用工具，不追求固定页数、泛工具榜单和漂亮但空泛的卡片。
语气：中文、具体、平实；技术细节服务读者决策。用户的真实经历与当前验证结果优先，不能把作者的目标当作已有能力或业绩。

## 工作流与记录
想法 → 待调研方向 → 可立项 → 写作 → 审稿 → 制图 → 发布复盘。Notion 是运营状态记录，本地是稿件与资产；没有自动双向同步。
动态状态应读取当前 Notion 或最新用户信息，不能用此文件冒充实时状态。未提供数据不填零；假设和示例清楚标注。
用户要求外部写入时使用已连接工具并检查目标，普通写作不自动发布或外联。使用内部材料写公开文章时复用 tech-doc-migration，但角色和结果必须符合事实，不能自动改写为个人主导。

## 视觉与工程
cBlog 品牌：柔和、舒缓、学习、个人记录。网站样式任务复用 style-optimization；当前运行时品牌配置是 apps/web/lib/brand.ts，品牌说明为 docs/brand-core.md。账号视觉若未定，不自动假设与网站完全一致。
工程命令以当前 package.json 为准；不加载完整外部代理框架、不安装后台记忆服务来完成普通内容任务。

## 已授权的成果同步收尾

用户已要求本项目审阅通过并本地落地的调研、梳理文档及图片同步到 Notion。完成此类成果后加载 [cblog-notion-sync](cblog-notion-sync/SKILL.md) 执行同步和回读核验，无需重复询问同一授权。目录不明确时新建 `docs/internal/notion-sync/YYYY-MM-DD-topic/`；未知远端分类时在已确认私人资料库下新建归档父页。图片未完成或冲突未处理不能声称同步完成。本规则是任务执行期收尾，不是后台或自动双向同步。
