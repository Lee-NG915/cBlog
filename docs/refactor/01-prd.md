# cBlog 重构产品需求文档（PRD）

- 版本：v1.0（2026-08-14）
- 状态：已评审确认，作为开发依据
- 关联文档：[技术设计](./02-technical-design.md) · [测试计划](./03-test-plan.md)

## 1. 背景与现状

cBlog 是单作者个人博客，Next.js 14 静态导出（`output: "export"`）部署 GitHub Pages。当前痛点：

| # | 现状 | 问题 |
|---|------|------|
| 1 | 单体工程，`apps/` 下混有三个与博客无关的未入库项目 | 结构混乱，无法承载"博客 + 管理端"多应用 |
| 2 | 文章元数据（标题/日期/状态/标签）散在各 md 的 frontmatter | 无法集中查看和管理内容与状态 |
| 3 | 分类硬编码在 `lib/site.ts` + 手动建目录 | 新建分类要改代码、建文件夹 |
| 4 | rightCapital / addx-ai 专栏是各自硬编码的独立路由和加载器 | 新建专栏成本高，逻辑重复 |
| 5 | 全流程依赖 IDE + 手动 git 操作 | 写作、改状态、发布没有统一入口 |
| 6 | Mermaid 点击后固定尺寸弹层，仅能滚动 | 大图浏览体验差 |
| 7 | 图片全量原图输出、Mermaid 进页即全部渲染 | 加载性能有优化空间 |

## 2. 目标与非目标

### 目标

1. 重构为 pnpm monorepo：博客前台（web）+ 管理平台（admin）+ 共享包（core）。
2. 引入轻量数据库（SQLite 单文件，随仓库提交）：文章/专栏的基本信息与状态以数据库为唯一真源；md 仍是正文源文件。
3. 本地管理平台：文章全生命周期（新建 → 写作 → 元数据 → 状态流转 → 发布上线）、分类管理、专栏管理、图片管理。
4. 分类/专栏零代码创建：管理端新建后前台自动生效，URL 全兼容。
5. Mermaid 大图查看器：缩放、拖拽、重置、适配。
6. 页面加载优化：图片管道、懒渲染、包体审计。
7. 部署方式不变：GitHub Actions 构建静态站点发布 GitHub Pages，构建时直接读取仓库内数据库。

### 非目标（明确不做）

- 管理端线上部署、多用户、鉴权体系（仅本地单人使用）。
- 评论、搜索服务等需要运行时后端的功能。
- 所见即所得富文本编辑（采用分屏 Markdown 源码 + 预览）。
- 文章/分类/专栏 slug 的修改（创建后锁定，改名仅限显示名；slug 变更列入 backlog）。
- 图片 srcset 多尺寸响应式（v1 仅压缩 + WebP，多尺寸列入 backlog）。

## 3. 用户与使用场景

唯一用户：博主本人，在本机使用。核心场景：

- **S1 写新文章**：打开管理端 → 新建文章（选分类、填标题）→ 编辑器写作（贴图自动落盘）→ 存草稿 → 本地预览 → 改为已发布 → 一键发布上线。
- **S2 管理存量**：列表按状态/分类/标签筛选 → 批量查看草稿 → 修改元数据或归档旧文。
- **S3 新开栏目**：新建分类或专栏 → 前台导航、列表页自动出现，无需改代码。
- **S4 读者看图**：文章内 Mermaid 图点击展开 → 滚轮缩放、拖拽平移看清大图细节。

## 4. 术语与状态定义

- **文章（post）**：`content/posts/<分类>/<年份>/<slug>/index.md`，属于唯一分类，可多标签。
- **专栏（collection）**：独立栏目（如 rightCapital、addx-ai），有落地页 + 按序号排列的文档列表，路径 `content/collections/<专栏>/`。
- **文章状态机**（专栏文档同规则）：

| 状态 | 前台生产构建 | 前台 dev 预览 | 管理端 |
|------|:--:|:--:|:--:|
| `draft` 草稿 | 不可见 | 可见（带草稿标识） | 可见 |
| `published` 已发布 | 可见 | 可见 | 可见 |
| `archived` 已归档 | 不可见 | 不可见 | 可见 |

  流转：draft ↔ published，published → archived，archived → draft/published。归档保留文件与数据库记录。
- **内容发布 vs 站点发布**：改状态为 `published` 只是内容可见性标记；「发布上线」指管理端执行 git 提交推送、触发 Actions 构建部署，两者独立。

## 5. 功能需求

> 验收标准（AC）为开发完成的判定依据，与测试计划用例一一映射。

### FR-1 Monorepo 工程结构

- FR-1.1 启用 pnpm workspaces；博客前台迁入 `apps/web`，管理端新建于 `apps/admin`，共享逻辑收敛到 `packages/core`。
- FR-1.2 现有 `apps/joyboy`、`apps/onepiece`、`apps/backend`（项目设计记录类资料，非实际配置）迁出至 `docs/projects/` 并按内部资料策略 gitignore；清理其中已被 git 跟踪的文件。
- FR-1.3 CI 工作流适配新目录，部署行为与产物不变。
- **AC**：重构前后两次生产构建的页面 URL 清单完全一致；`pnpm dev:web` / `pnpm dev:admin` / `pnpm build` 可在仓库根一键运行。

### FR-2 数据库与元数据真源

- FR-2.1 SQLite 单文件 `data/blog.db` 随仓库提交；表含 posts、categories、tags、post_tags、collections、collection_items（见技术设计 §4）。
- FR-2.2 一次性导入脚本：扫描现有 frontmatter、rightCapital 文件名序号、addx-ai 硬编码元数据，全量建库；可重复执行（幂等 upsert）。
- FR-2.3 回写机制：管理端每次保存 = 写数据库 + 单向回写该 md 的 frontmatter（字段顺序固定，保证 diff 稳定），md 始终自包含。
- FR-2.4 重导入命令：显式执行时以文件 frontmatter 为准覆盖数据库（兜底手改文件/数据库损坏场景）；日常以数据库为准。
- FR-2.5 漂移检测：前台构建时校验 frontmatter 与数据库一致性，不一致输出警告（不阻断构建）。
- **AC**：导入后数据库记录数 = 现有 md 文件数；任一管理端保存动作后，数据库、frontmatter、页面展示三处一致。

### FR-3 管理端 · 文章管理

- FR-3.1 文章列表：全量展示（含草稿/归档），支持按状态、分类、标签筛选与标题关键词搜索，按日期倒序。
- FR-3.2 新建文章：选分类 + 填标题（slug 自动生成、可改、校验唯一与合法性）→ 自动创建 `content/posts/<分类>/<当前年份>/<slug>/index.md` 脚手架 + 数据库记录，初始状态 draft。
- FR-3.3 编辑器：CodeMirror Markdown 源码 + 右侧实时预览分屏；预览渲染与前台同管道（含 Mermaid、GFM）；防抖刷新；`Cmd+S` 保存；有未保存变更离开时提示。
- FR-3.4 元数据表单：标题、日期、摘要、标签（可输入新建）、封面图、所属分类（可调整，调整仅改数据库与 frontmatter，不移动文件，v1 不改 URL——slug 不变）。
- FR-3.5 状态流转：按 §4 状态机操作，含状态变更确认。
- FR-3.6 删除：软删除——文件移入 `content/.trash/`（gitignore），数据库记录删除；需二次确认。
- **AC**：S1 场景全流程可在管理端完成，不打开 IDE。

### FR-4 管理端 · 分类管理

- FR-4.1 分类列表（含每类文章数）、新建（slug/名称/描述/排序）、编辑（名称/描述/排序）、删除。
- FR-4.2 新建分类自动创建 `content/posts/<slug>/` 目录；有文章的分类禁止删除。
- FR-4.3 前台分类页、导航、新建文章的分类下拉自动包含新分类，零代码改动。
- **AC**：新建分类 → 该分类下发一篇文章 → 前台构建后 `/categories/<slug>/` 与导航正常呈现。

### FR-5 管理端 · 专栏管理

- FR-5.1 专栏 CRUD（slug/名称/描述/排序）；新建自动创建 `content/collections/<slug>/` 目录；有文档的专栏禁止删除。
- FR-5.2 专栏文档管理：新建（生成 md + 记录）、编辑（同 FR-3.3 编辑器）、状态流转、拖拽排序（排序存数据库）。
- FR-5.3 存量迁移：`docs/rightCapital`、`docs/addx-ai` 内容迁入 `content/collections/`，原 URL（`/rightCapital/...`、`/addx-ai/...`）保持不变。
- FR-5.4 前台专栏采用统一通用模板（落地页 + 文档页），样式基于现 rightCapital 页面泛化。
- **AC**：迁移后原有专栏全部 URL 可访问且内容一致；管理端新建专栏 + 文档后前台自动出现。

### FR-6 管理端 · 图片管理

- FR-6.1 编辑器内粘贴/拖入图片：自动保存到该文章目录 `assets/` 子目录（重名自动加后缀），并在光标处插入相对路径引用 `![](./assets/xxx.png)`。
- FR-6.2 封面图上传同样落到文章 `assets/` 目录，数据库与 frontmatter 存相对路径。
- FR-6.3 兼容存量：`public/images/` 下现有图片及 md 内绝对路径引用继续有效，不迁移。
- **AC**：贴图后本地预览与生产构建均正确显示（含 GitHub Pages basePath 场景）。

### FR-7 管理端 · 发布上线（git 集成）

- FR-7.1 发布页展示内容相关变更清单（限 `content/`、`data/blog.db`）与当前分支、领先/落后远端状态。
- FR-7.2 一键发布：自动生成可编辑的 commit message → `git add`（白名单路径）→ commit → push，推送成功给出 Actions 构建链接。
- FR-7.3 护栏：仅提交白名单路径；存在白名单外变更时明确提示"请在 IDE 处理"；push 冲突/失败时给出原因与手动处理指引，绝不 force push。
- **AC**：S1 场景最后一步在管理端点击发布后，GitHub Pages 上线新文章。

### FR-8 前台 · 分类/专栏动态化与 URL 兼容

- FR-8.1 分类、专栏、导航数据源全部改为数据库（构建时读取），删除 `lib/site.ts` 分类硬编码与 `lib/rightCapital.ts`、`lib/addxAi.ts` 专用加载器。
- FR-8.2 专栏路由通用化：根级动态段 `/[collection]/` 与 `/[collection]/[slug]/`，`generateStaticParams` 从数据库枚举；与现有静态路由（/about、/posts 等）共存。
- FR-8.3 URL 兼容红线：重构前所有已发布 URL 在重构后不变（sitemap 全量比对）。
- FR-8.4 sitemap、RSS（如有）、OG 信息随数据库数据生成。
- **AC**：sitemap 前后对比零丢失；草稿/归档语义符合 §4 状态表。

### FR-9 Mermaid 交互查看器

- FR-9.1 点击图例进入全屏查看器：滚轮缩放（以光标为锚点）、按住拖拽平移、双指捏合与单指拖动（触摸）、双击放大。
- FR-9.2 工具栏：放大、缩小、重置、适配宽度；缩放范围 0.25x–8x；ESC 与点击遮罩关闭。
- FR-9.3 打开时默认适配窗口宽度居中；渲染失败保留现有错误兜底提示。
- FR-9.4 内联预览自适应高度（上限约束），保持"点击查看大图"提示。
- **AC**：一张超出屏幕的大图可通过缩放 + 拖拽查看任意局部，交互流畅（无明显掉帧）。

### FR-10 性能优化

- FR-10.1 Mermaid 懒渲染：图例进入视口才渲染（当前进页全量渲染）。
- FR-10.2 图片构建管道：随文档图片同步进构建产物时压缩并转 WebP（保留原格式兜底），引用自动重写。
- FR-10.3 大组件懒加载（KnowledgeGraphExplorer 等）；引入 bundle 分析，产出基线报告。
- **AC**：见 §6 性能预算；含 Mermaid 的长文首屏不因图例渲染阻塞。

## 6. 非功能需求（NFR）

| ID | 要求 |
|----|------|
| NFR-1 | URL 兼容：现有已发布 URL 100% 保持（FR-8.3 红线） |
| NFR-2 | 性能预算：文章页首屏 JS 不高于重构前基线；Lighthouse（移动端）Performance 不低于重构前基线 |
| NFR-3 | 管理端及其依赖不得进入 web 生产构建产物 |
| NFR-4 | 数据安全：文件写入原子化（临时文件 + rename）；所有管理端写路径限制在 `content/`、`data/` 白名单内，slug 严格校验防路径穿越 |
| NFR-5 | 构建确定性：CI 无需任何新增 secret/外部服务，checkout 即可构建 |
| NFR-6 | 环境：Node 20、pnpm 9（与 CI 一致） |

## 7. 里程碑

| 阶段 | 内容 | 退出标准 |
|------|------|----------|
| Phase 0 | 仓库清理：迁出 apps 下三个记录类项目 | `apps/` 清空，git 状态干净 |
| Phase 1 | Monorepo 骨架：web 迁入 `apps/web`，CI 适配 | 构建产物 URL 清单与迁移前一致（MIG 用例） |
| Phase 2 | core 包 + 数据库 + 导入脚本 + web 改读数据库 | 产物仍等价；导入幂等；漂移检测生效 |
| Phase 3 | 专栏通用化 + 内容迁入 `content/collections/` | 专栏 URL 全兼容（MIG 用例） |
| Phase 4 | 管理端 MVP：文章/分类/专栏/图片/发布 | S1–S3 场景走通（ADM 用例） |
| Phase 5 | Mermaid 查看器 + 性能优化 | FR-9/FR-10 AC 达成，性能基线报告 |

每阶段独立可合并、可部署，主分支始终可发布。

| D1 | 管理端形态 | 仅本地使用，无鉴权 |

| D10 | 数据库选型 | SQLite 单文件入库 + Drizzle ORM |
