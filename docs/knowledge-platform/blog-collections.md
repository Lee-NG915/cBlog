# 博客专栏管理

后台“博客专栏”管理已发布专栏的可见性；私人的项目和学习路径仍用于组织笔记，两者互不替代。

| 可见性 | 专栏列表、站内搜索 | 专栏与文章原链接 |
| --- | --- | --- |
| 公开展示 | 显示 | 可访问 |
| 仅链接访问 | 隐藏 | 可访问，noindex |
| 仅后台 | 隐藏 | 部署后返回 404 |

选择可见性，点击“应用并更新博客”，确认影响范围后提交。排队、构建和核验期间展示原有线上状态；核验成功后更新为新状态。失败保留原状态，提供重试和运行日志。可见性操作不会提交工作草稿。

## 数据与发布边界

- D1 migration `0006_blog_collections.sql` 添加专栏目录表：slug、名称、说明、顺序及现有文章 ID / 路由关联，不复制文章。
- 初次目录从当前成功部署的 `published-content` 不可变归档及其 `legacyContentRef` 生成。仅关联 D1 中已存在的文章，不从工作目录导入或恢复私稿。
- 目录表是文章关联信息；最新成功发布的 manifest 中 `collectionVisibility` 才是线上可见性的来源。旧 manifest 默认公开展示，保留当前站点行为。
- 隐藏时保留原文及其已发布清单。恢复时从同一个不可变内容源重建，保留正文、版本、时间和其他文章。个别已下线文章仍受 withdrawals 约束，不会因恢复专栏而重新上线。
- 隐藏的专栏不能直接发布单篇文章。后台引导先调整专栏可见性，避免“发布成功但文章不可见”。
- POST `/api/v1/blog-collections/:slug/visibility` 使用会话鉴权、CSRF、发布版本 CAS、活动任务互斥和请求 ID 幂等；要求当前发布已有核验后的线上文章清单。
- 构建时只允许删除明确指定的专栏目录与子路由；其他文章、时间和其他专栏的状态必须保持。隐藏的正文不进入公开目录、搜索和 publication.json。
- 回执核对完整线上文章清单、目标专栏状态和目录/子路由 HTTP 状态；后台不会仅凭 GitHub 接收请求标记完成。

## 验证

`pnpm knowledge:test` 覆盖隐藏、恢复、仅链接访问、旧链接仍存在时拒绝成功回执、内容丢失检测、并发/过期请求、重复提交、私稿保留与单篇发布拦截。

`node --test scripts/knowledge/collection-visibility.test.mjs` 覆盖静态模型过滤、恢复、noindex、无关路由保留和仅可见性变更约束。

`pnpm knowledge:e2e blog-collections.spec.ts` 在隔离的浏览器数据下验证桌面/手机的确认、取消、处理中、失败重试入口和最终状态。生产环境验收保持原有可见性，不通过临时下线用户文章来测试。
