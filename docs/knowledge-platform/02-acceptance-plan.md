## 1. 验收原则与完成门槛

“文档已完成”与“应用已通过验收”分开。所有下列用例初始状态均为 **NOT_RUN**，没有真实证据不得标 PASS。模拟器测试不能替代免费账户远程验证，桌面浏览器模拟尺寸不能替代手机中文输入法真机测试。

状态：NOT_RUN / PASS / FAIL / BLOCKED / N/A。N/A 必须写适用性理由；不能将尚未实现的已承诺功能标 N/A。BLOCKED 写依赖和恢复条件，不能算通过。

缺陷等级：P0 数据泄漏/丢失/意外付费；P1 核心操作失败、冲突覆盖、迁移缺失；P2 明显易用性/非核心功能缺陷；P3 不影响任务完成的视觉细节。P0/P1 必须清零；核心路径及移动端适用用例全部通过。P2 必须有负责人、处理计划和明确接受记录，不能自行豁免权限/保真/免费限制。

| Gate | 交付门槛 | 必需用例 |
| --- | --- | --- |
| G0 | 免费能力和候选技术原型成立 | ENV-01～04、PERF-01、ED-06、ED-07 |
| G1 | 数据与权限可靠 | DATA-01～06、AUTH-01～06 |
| G2 | 双端工作台和图片可用 | ED-01～08、MEDIA-01～05、UX-01～04 |
| G3 | 阅读与全文搜索可用 | READ-01～05、SEARCH-01～04、A11Y-01～03、PERF-02～04 |
| G4 | 可安全发布/撤回/回滚 | PUB-01～07、QUOTA-01～04 |
| G5 | 自然语言检索与引用问答可开放 | AI-01～07、SEARCH-05、PERF-05 |
| G6 | 允许迁移切流 | MIG-01～05、OPS-01～04；G0～G4 已通过 |

基础上线需 G0～G4 和 G6；完整需求交付还需 G5。AI 未通过时可以关闭该入口上线基础站，但交付记录必须标明自然语言功能未完成。

## 3. 环境、样本和证据规范

### 3.1 环境矩阵

- 本地：隔离 SQLite/D1 模拟器、KV fixture、AI stub，可确定性注入超时、乱序和配额错误。
- Cloudflare 预览：真实 Free 账户、独立资源、合成数据；记录 compatibility date、binding、代码 commit、部署 ID、模型 ID。不得为了跑测试开通付费产品。
- 桌面：执行时最新稳定 Chrome、Firefox、Safari；记录实际版本和 OS。
- 真机：iOS Safari 与 Android Chrome，各记录机型、系统、输入法、键盘、网络。至少一次微信等内置浏览器可用性探测，发现不支持则提供“用浏览器打开”说明，不替代主浏览器测试。
- 视口：320、360、390、768、1024、1280、1440px；390/1440 为主要截图基线，其他尺寸测断点、横滚和遮挡。
- 网络：正常 Wi-Fi、移动网络、离线、400 ms 延迟/1 Mbps 限速；配额耗尽通过注入测试，不故意耗光共享账户。
- 身份：匿名、所有者、非所有者 GitHub 用户、过期会话、吊销的构建/索引凭证。

### 3.3 证据

每个用例记录 case ID、时间、commit、环境、设备、输入 fixture、步骤、实际结果、状态、截图/录屏/日志、缺陷链接。证据文件以 `<caseId>/<timestamp>-<device>` 命名。分享证据脱敏，私人 canary 仅使用合成值。对“没有泄漏”的验证扫描 HTML、JS、JSON、搜索索引、sitemap、图片清单与日志，不能只看页面肉眼结果。

## 9. AI 质量、权限和免费降级

### 9.1 固定质量集

在 F09 冻结 20 个有答案问题，组成：精确术语五个、中文同义五个、技术跨篇三个、商业跨篇三个、学习顺序两个、中英混写两个。另设五个无答案问题。每题由人工先标注 relevant note/chunk IDs、支持的关键事实和应拒答内容；不要用被测模型给自己的答案打分。

示例问题仅用于建立标注集，不预设现有笔记一定包含答案：

- “广告有人点击但是没人下单，先检查什么？”
- “我想系统了解公司的商业化，应按什么顺序阅读？”
- “付费获客与 Paid Ads 的笔记有哪些？”
- “保存期间继续打字，为什么内容会被覆盖？”
- “上个月公司广告准确花费多少？”（语料无记录时必须拒答）

质量标准：20 个有答案问题中，至少 18 个 top5 命中一个人工相关笔记（Hit@5 ≥90%）；至少 16 个相关来源集合的 Recall@5 ≥80%。跨篇题 top6 上下文应覆盖标注的必要来源；不能只命中一篇就认定跨篇问题通过。冻结数据集后记录 lexical/semantic/hybrid 三者分数，混合结果不低于全文基线。

引用 URL 与 sourceId 有效率 100%；人工抽查每个回答的事实性陈述，受引用片段支持率 ≥95%；涉及公司具体数字、行为或状态的无依据断言为零容忍。五个无答案问题均明确不足，不伪造答案/引用。同一固定配置运行三轮，报告每轮结果，不能只取最好一次。质量不达标则保持“找笔记”，关闭生成入口。

| ID | 前置/步骤 | 预期与证据 |
| --- | --- | --- |
| AI-01 | 执行固定质量集三轮，存脱敏 query、配置、topK、回答和人工评分 | 达到上述 Hit/Recall/引用/事实支持门槛；报告包含失败项 |
| AI-02 | 更新/删除笔记后索引任务延迟；模型换维度；旧 generation 残留 | 回查过滤旧结果；不混维度；重建期间全文可用，状态明确 |
| AI-03 | 同一 job 重领、lease 超时、向量写入后 callback 丢失；修订更新中途发生 | 幂等，无错误 active generation；新版本最终可索引，过时 job 不覆盖 |
| AI-04 | 匿名调用 AI；伪造私人 candidate IDs；模型生成中撤销/删除来源 | 拒绝越权；最终返回前再次校验，失效回答不返回；私人来源不进日志 |
| AI-05 | F10 提示注入、假引用，要求执行工具/外网/暴露系统提示 | 不执行工具；只使用有效 sourceId；输出安全；拒绝资料中的越权指令 |
| AI-06 | 注入 429、付费模型 403、5xx、超时、每日预占额度竞争 | 不升级/充值；停止重试风暴；计数原子；全文降级可继续操作 |
| AI-07 | 来源修改后点击旧回答引用；空检索；超长问题和上下文 | 版本差异有提示；空证据不编造；长度限制明确，输出不超应用预算 |

## 11. 性能目标与测量方式

以下是验收目标，不是当前测量结果。每次记录样本数、数据规模、网络、设备、浏览器、模型、cold/warm 状态。性能不达标先优化/缩小单次工作，不提高到付费套餐。

| ID | 测量方式 | 目标 |
| --- | --- | --- |
| PERF-01 | 真实 Free 预览对鉴权读取、CAS 保存、列表、1 MiB 图片上传分别至少 100 次；读取平台 CPU 指标 | 各端点 p95 CPU ≤8 ms，零 CPU 超限错误；平台 CPU 指标不可得则 BLOCKED，不能用墙钟替代 |
| PERF-02 | 390px 中档 Android，移动网络；公开 F01/F02 各五次冷加载 Lighthouse/lab trace | 各页 LCP 中位数 ≤2.5s、CLS ≤0.1；实验室结果不冒充线上 p75 Core Web Vitals |
| PERF-03 | 真机输入长文、开目录、切搜索结果，至少 50 次交互 trace | 关键交互 p95 响应 ≤200ms；记录长任务，输入期间无持续 >200ms 阻塞 |
| PERF-04 | F11 两规模，桌面/手机各 30 次查询，分别测首次索引和 warm query | warm 全文查询 p95 ≤300ms；90 条基线语料首次可搜索 ≤3s（Wi-Fi）；超规模分批有进度 |
| PERF-05 | Free 模型，20 次正常请求；记录首结果、总耗时和 Neurons 差值 | 语义结果 p95 ≤3s，问答总耗时 p95 ≤20s；30s 超时降级；实测每次消耗，不宣称固定日问答数 |

公开站压缩后页面首屏 JS 目标 ≤200 KiB，不包含懒加载编辑器/搜索索引；目标超出必须列主要依赖与优化决定。编辑器不得被公开阅读页加载。GitHub 单次基线发布构建目标 ≤5 分钟；失败重试纳入月度预算估算。

## 13. 手工体验验收任务

在手机与桌面分别由使用者完成，不由开发者代点；记录耗时、误触、返回与困惑位置。以下是任务目标，不用虚假的“满意度百分比”代替观察。

1. 新建“商业化学习计划”，写三段文字，插入截图，离线补充，联网恢复。
2. 把它放入“商业与增长”，加入一个项目并编排三篇顺序；沿路径阅读下一节。
3. 在长技术文找到某一章节，读宽表、复制代码，切换较大字号。
4. 用记不清术语的自然语言找一篇笔记，再问跨篇问题，点击引用核实。
5. 发布公开笔记后撤回；能解释“本机已保存”“已同步”“已发布”“撤回中”的区别。

通过条件：两端任务均能独立完成；无必须改用桌面的步骤；无内容丢失或误公开；所有困惑点形成缺陷或可追踪改进项。主观排版偏好由用户实际阅读后确认，不以组件库默认样式作为验收依据。
