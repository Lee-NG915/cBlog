# 博客发布时间与编辑时间

在后台打开文章，点击「编辑」→「文章设置」→「发布展示时间」。时间统一按 UTC+8 输入，可精确到分钟。保存后，点击「发布文章」或「更新博客」，部署成功后访客看到新日期。此字段仅控制展示与文章列表排序，不是定时发布。

- 留空：沿用该文章冻结的默认发布时间；新文章在首次发布时记录。
- 设置或修改展示日期：发布时间使用自定义值，正文编辑时间不变。
- 修改标题、正文、分类或标签：后台记录内容编辑时间；更新博客后在正文末尾显示「编辑于」，发布时间保持原值。
- 只保存、归档、改变草稿状态：不会自动改动已经上线的页面。
- 下线再发布：保留默认发布时间和日期设置，不重置为重新部署时间。
- 历史文章有原发布日期时保留它；历史专栏未记录日期的，使用迁移时冻结的基准值，自定义展示日期独立保存。

## 数据与发布契约

`notes.display_published_at` 保存可编辑的展示时间；`content_updated_at` 保存最近内容编辑时间；原有 `updated_at` 继续作为实际保存审计时间。字段缺省的旧客户端保留现有展示时间，显式 `null` 清空。

不可变发布清单的 `publicationDates` 按文章 ID 保存默认发布时间、展示时间、编辑时间与路由。构建先合并冻结的历史内容和已发布快照，再应用日期元数据。日期可以更新，工作草稿不会因此替换线上正文。公开的 `publication.json` 与后台回执包含同一套日期。

批量日期整理必须使用 `dates` 意图，构建检查全部文章的正文、标题、标签等内容不变；部署回执核验数量、路由、内容摘要和三个日期全部一致后才确认成功。单篇的日期或正文修改继续走普通的「更新博客」流程。

## 验证

- API 测试：保存、旧客户端兼容、正文编辑、清空、下线再发布、部署日期不匹配拒收。
- 构建测试：独立博文和专栏的日期覆盖、日期格式、路由防错、禁止日期整理混入正文修改。
- 浏览器：桌面和手机保存/重载/清空；逐篇检查发布时间与编辑时间；320px、390px、1440px 的布局与正文末尾位置。
