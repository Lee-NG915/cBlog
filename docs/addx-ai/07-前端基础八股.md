# 07 · 前端基础八股（手撕 + 概念）

按真题情报：**带 TTL 的 LRU 最高优先**；其余按手撕 → JS → React → 浏览器 → 网络 → TS → 算法。

---

## 手撕：带 TTL 的 LRU（该公司真题）

结构：

- `Map`：O(1) 查节点。  
- **双向链表**：维护 recency（头最旧 / 尾最新，或相反，说清即可）。  
- 节点：`key, value, expireAt`。

操作：

- `get`：不存在或过期 → 删并返回空；命中 → 移到最新端。  
- `put`：已存在则更新值与过期、移到最新；新 key 超容量则淘汰最旧。  
- 容量：只计未过期有效条目（或 get/put 时惰性删）。

TTL：

- **惰性过期**：读写时检查 `now > expireAt`（主路径，必讲）。  
- **定时清理**：可选扫链表/桶，防大量冷 key 占内存。  
- 过期算未命中，不延长 TTL（除非题目要求 sliding）。

口述顺序：需求 → 结构选型 → get/put → 过期策略 → 复杂度 O(1) → 边界（capacity=0、expire=0）。

## 其它手撕要点

### 防抖 / 节流

- 防抖：停下来才执行（搜索输入）。  
- 节流：固定间隔最多一次（滚动）。  
- 注意：`this`、参数、leading/trailing、cancel。

### 深拷贝

- 手写：递归 + `WeakMap` 处理循环引用。  
- 类型：Date/RegExp/Map/Set/Array；函数/DOM 通常不拷或按需求。  
- `structuredClone` / JSON 局限（提一句）。

### Promise.all / allSettled

- `all`：全成才成，一败即败。  
- `allSettled`：等全部结束，返回 status 列表。  
- 手写 all：计数 + 按序填数组。

### call / apply / bind

- 改 `this`；apply 参数数组；bind 返回绑定函数（可柯里化）。  
- 手写 bind：保存 args，`new` 时忽略绑定 this。

## React

### Fiber

- 可中断单元；reconcile 与 commit 分离；支持优先级/并发。  
- 双缓存思想（能点到即可）。

### Hooks

- `useState` 快照；批更新。  
- `useEffect`：依赖比较、清理函数、别当同步渲染用。  
- 闭包陷阱：过期 state → 函数式更新或正确依赖。  
- 规则：顶层调用、依赖诚实。

### 并发特性

- 可中断渲染、useTransition/useDeferredValue 降紧急度。  
- 与 INP：减少紧急更新阻塞输入。

### Suspense（服务端 vs 客户端）

- **服务端 Suspense**：控制 HTML streaming（chunked transfer encoding）。`<Suspense fallback={<Skeleton/>}>` 先发 fallback HTML，异步数据就绪后流式补充真实内容。用户先看骨架，再渐进看到完整页面。
- **客户端 Suspense**：控制 loading 状态。`React.lazy` 代码分割、`useSuspenseQuery` 数据获取时展示 fallback。
- 同一个 `<Suspense>` 在服务端和客户端触发机制不同：服务端 = streaming 边界；客户端 = loading 边界。

### 性能优化（高频必考）

**React.memo / useMemo / useCallback**

- `React.memo`：浅比较 props，props 不变则跳过重渲染。适合：纯展示组件、列表子项。
- `useMemo`：缓存**计算结果**。适合：昂贵计算、引用稳定的对象/数组（防子组件无意义重渲染）。
- `useCallback`：缓存**函数引用**。适合：传给 memo 子组件的回调、effect 依赖中的函数。
- **误区**：不要所有地方都加 → memo 本身有比较成本；浅比较失败反而更慢。只在 Profiler 确认瓶颈后加。

**虚拟列表（Windowing）**

- 原理：只渲染可视区域 + 上下 buffer 的 DOM 节点，其余用空白占位。
- 库：`react-window`（轻量）/ `react-virtuoso`（功能更多、支持动态高度）。
- 适合：商品列表（PLP）、搜索结果、订单历史等大量重复项场景。
- 关键参数：`itemSize`（固定/动态）、`overscanCount`（预渲染行数）。

**重渲染排查**

- React DevTools Profiler → Highlight updates → 找哪些组件不该渲但渲了。
- `why-did-you-render`：开发环境自动提示无意义重渲染原因。
- 常见根因：父组件每次 render 创建新对象/函数 → 子组件 props 引用变了。

### Error Boundary

- **只能用 class 组件**：`static getDerivedStateFromError(error)` 返回 fallback state；`componentDidCatch(error, info)` 做上报。
- **不捕获**：事件处理器（用 try-catch）、异步代码（Promise）、SSR、自身错误。
- **项目联动**：`componentDidCatch` 内调 `captureStructuredError` 上报 Sentry，带 `domain` / `page_type` context。
- **策略**：页面级 boundary 兜底白屏 → 模块级 boundary 隔离非核心模块崩溃（如推荐模块挂了不影响 PDP 主体）。

### CJS vs ESM（与 Tree Shaking 联动）

- CJS：`require()` 运行时、同步、动态路径 → 打包器无法静态分析 → **不能 tree shake**。
- ESM：`import` 编译时、静态结构 → 打包器可分析未使用 export → **可 tree shake**。
- **Barrel export 陷阱**：`index.ts` re-export 所有 → 即使只 import 一个函数，整个 barrel 被拉入。
- **项目实践**：`next.config.js` 配置 `optimizePackageImports`（含 `@mui/joy`）让 Next 自动改写 import 路径。
- 面试句：「ESM 的静态 import 是 tree shaking 的前提；barrel export 和 CJS 混用是最常见的 shake 失效原因。」

### AbortController / 竞态处理

- `fetch` 传 `signal: controller.signal` → 调 `controller.abort()` 取消。
- **React useEffect cleanup**：`return () => controller.abort()` 防组件卸载后 setState。
- **搜索竞态**：用户快速输入 → debounce + 每次新请求前 abort 上一次 → 保证只展示最新结果。
- **RTK Query**：内置请求取消（组件卸载自动 abort）；手动用 `abort()` on subscription。

### RSC（与项目打通）

- 默认 Server；`'use client'` 边界；少下发 JS；数据在服务端取。  
- **RSC 产物是 RSC Payload（React Flight 格式），不是 HTML**。
- RSC Payload = Server Component 已展开为原生元素 + Client Component 占位引用（`@ref + props`）。
- 三阶段：**RSC 执行**（→ Payload）→ **SSR**（Payload + Client Component → HTML）→ **Hydration**（只 hydrate Client 子树）。
- 后续导航只请求 Payload（不请求整页 HTML），体验像 SPA。
- Server Component 代码永不下发客户端 → 减 bundle。
- 项目中 Fortress 基础组件已标 `'use client'`；layout 用 `SentryContextProvider`；page 必调 `setGlobalSentryContext`。

### i18n（与项目打通）

- 技术栈：`i18next` + `i18next-icu`（ICU MessageFormat），**不是** i18next 原生复数格式。
- Locale 来源：cookie `preferred_language`（BCP-47，如 `en-SG`）为 single source of truth。
- 服务端/客户端一致性：middleware 写 cookie → `getLocaleServer()` 和 `getLocaleClient()` 都读同一 cookie。
- 9 个 namespace：shared / modules/{cart,user,product,order,checkout,promotion,search} / error。
- 5 个 locale：`en-US / en-CA / en-SG / en-AU / en-GB`（全英文，目前各 region 只有一个 locale）。
- 复数：ICU `{count, plural, =1 {# item} other {# items}}`。
- 富文本：`<Trans>` 组件 + `components` prop 映射 HTML 标签为 React 元素。

## 浏览器

### 渲染流程

- DOM/CSSOM → Render Tree → Layout → Paint → Composite。  

### 重绘 / 回流

- 回流改几何；重绘改外观；合成层优化。  
- 批读批写、避免强制同步布局。

### 缓存（与 ISR/Redis 打通）

- 强缓存：Expires / Cache-Control。  
- 协商：ETag / Last-Modified → 304。  
- CDN：边缘命中降延迟；与「多 Pod 共享应用缓存」分层讲：浏览器/CDN/应用 Redis 各一层。

### 跨域

- 同源策略；CORS 预检；简单/非简单请求。  

### XSS / CSRF

- XSS：转义、CSP、HttpOnly。  
- CSRF：SameSite、CSRF Token、不滥用 Cookie 鉴权于危险操作。

## 网络

- HTTP/2：多路复用、头部压缩；减少队头阻塞（相对 HTTP/1.1）。  
- HTTPS：TLS 握手、证书；中间人防护。  
- CDN：就近、缓存、回源；全球化站点结合多市场部署经验讲。  
- DNS → TCP/TLS → 请求 → 响应。

## 算法：合并区间（该公司真题相关）

- 先按起点排序。  
- 扫一遍：能合并则扩 end，不能则推入结果。  
- 复杂度 O(n log n)。  
- 变体：插入区间、相交判断——同一套排序扫描思路。
