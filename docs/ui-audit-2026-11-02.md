# cBlog 全站 UI 与交互审计

审计日期：2026-11-02（Asia/Singapore）  
范围：Cloudflare 笔记后台与 GitHub Pages 公开博客。目标是让读者能找到并读完内容，让作者能理解保存、上线、更新和下线的实际结果。

## 结论与版本方向

保留 Color 手记的暖纸色、陶土色和安静的卡片布局，调整信息层级、阅读排版、导航与操作反馈。此次是前端体验更新，沿用线上内容快照；不把本地文档、后台草稿或已下线文章加入发布清单。

后台的关键语义继续保持：保存只保存文稿；发布/更新针对选中的一篇文章；下线需要部署完成并核验后才算生效；归档和回收站保留正文。博客状态不能从文稿的草稿/公开字段推断，必须来自实际发布记录。

## 审计方法与覆盖

- 公开站：遍历全部 102 个导出 HTML 入口，包括 24 篇文章、60 篇专栏笔记、4 个专栏目录、6 个主题页，以及首页、主题总览、搜索、关于、品牌、404 和旧地址入口。每个入口检查 1440、390、320 CSS 像素宽度，合计 306 次页面检查。
- 后台：知识库、学习路径、项目、收件箱、博客发布、搜索、归档、回收站、品牌九个主界面；另验证编辑器、文章设置、阅读预览、长文目录、目录管理弹窗、版本恢复、图片上传与发布操作。
- 交互：键盘导航、目录定位、图表放大与关闭、主题切换、搜索及分页、刷新/浏览器返回、保存中继续输入、离线草稿恢复、保存冲突、发布失败与重试、下线中/失败的真实状态。
- 可访问性：axe-core 4.11.0 扫描公开站 10 个代表模板和后台 9 个主界面，覆盖桌面/手机、明暗主题；配合人工截图和键盘检查。自动工具不能替代完整的读屏器或真实手机验收。
- 内容保护：以当前已发布快照为构建输入；部署前后对比 publication.json、公开路由、已下线路由及后台文稿指纹。

测试在隔离本地 SQLite 与模拟接口上执行，不向线上数据库写测试笔记。浏览器使用 Chrome；未进行真实 iOS Safari、Android 设备或完整读屏器测试。

## 问题清单与处理

| 编号  | 优先级 | 观察到的问题及影响                                                       | 修复                                                                                                     |
| ----- | ------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| UI-01 | P1     | 全站正文与标题使用等宽字体，长中文标题过大，文章首屏被标题和重复摘要占满 | 改用系统中文字体；统一标题尺寸；缩小推荐卡片标题；自动摘录与开头重复时仅在正文展示，保留原始内容和元数据 |
| UI-02 | P1     | 窄屏长英文标题可撑宽页面；宽表格与代码不易操作                           | 长词换行，正文容器允许收缩，表格保留可横向阅读的列宽；表格及代码区域支持键盘聚焦滚动                     |
| UI-03 | P1     | 内容淡入依赖 JavaScript，一旦脚本未完成可能看不到正文                    | 正文首屏即显示；只保留渐进增强的首页动效；尊重减少动态效果偏好                                           |
| UI-04 | P1     | 首页后续文章没有清晰的用户控制；缺少全站搜索入口                         | 增加明确的“再看 9 篇”按钮和数量反馈；增加公开文章/专栏搜索、主题筛选、空结果恢复和继续查看               |
| UI-05 | P1     | 专栏入口难找，手机阅读时没有目录和前后篇                                 | 主题页增加四个专栏入口；文章及专栏笔记增加折叠目录；专栏提供上一篇/下一篇                                |
| UI-06 | P1     | 图表放大时键盘焦点可以离开查看器，关闭后无法回到原处                     | 使用模态 dialog，Tab 循环、Escape 关闭，关闭后焦点返回图表；工具按钮支持手机换行                         |
| UI-07 | P1     | 后台博客发布入口埋在目录下方；长目录占用大量空间                         | 发布入口移入主导航；知识领域可以折叠；当前页面/分类有明确选中语义                                        |
| UI-08 | P1     | 后台搜索结果截断且没有继续查看；归档条目和列表计数不一致                 | 搜索每次展示 30 条并可继续查看；显式选择是否搜索归档；主题、路径和项目统一排除已归档条目                 |
| UI-09 | P1     | 编辑器固定工具栏可能与顶栏叠在一起；弹窗错误显示在弹窗外                 | 根据桌面/手机顶栏高度定位工具栏；创建/重命名/排序的错误、忙碌状态留在操作现场                            |
| UI-10 | P1     | 发布状态尚未加载时，数量可能误显示成全部草稿                             | 未知状态显示“—”；使用“未上线”准确描述数量；文章按最近修改排序，便于逐篇处理                              |
| UI-11 | P2     | 返回或刷新可能丢失当前目录/发布页位置                                    | URL 保存当前页面、分类与阅读文章；刷新与浏览器返回恢复对应位置                                           |
| UI-12 | P2     | 次要文字偏淡，暗色背景选择器不匹配；部分图标目标过小                     | 提高次要文字对比度、修复暗色背景；导航和主题切换等主要控件达到 44px 点击区域                             |
| UI-13 | P2     | 多篇文章含两个主标题，404 嵌套 main，品牌样例能获得焦点                  | 页面只保留一个 h1 和 main；正文 h1 在显示层转换为 h2；品牌预览 inert；增加跳至正文入口                   |
| UI-14 | P2     | 旧 joyboy-knowledge-map 链接跳到未公开的地址                             | 保留旧入口，跳转到现有公开的工程实践索引，不额外公开原草稿                                               |
| UI-15 | P2     | 后台复制代码失败无反馈，图表加载和暗色切换不清楚                         | 复制成功/失败反馈；代码区域避免按钮覆盖；图表显示加载状态，适配暗色，语法失败时保留源码                  |
| UI-16 | P2     | 网络失败可能被表现成普通登录页；失效笔记地址缺少恢复路径                 | 提示连接失败与重试；失效笔记提供回收站/知识库入口；退出失败保留错误反馈                                  |

P1 表示影响阅读、找内容或完成主要操作；P2 表示次要可用性与一致性问题。不是安全漏洞评级。

## 实现约束

- 搜索只索引已经公开的标题、摘要、标签与专栏，不读取私密后台文稿；当前 84 个公开内容项全部可查。
- 页面排版处理不改 Markdown 原文、正文版本、发布时间或文稿状态。
- 前端更新使用 `frontend-publish.yml`，从当前线上部署解析不可变内容来源，并在部署前检查内容身份没有变化。
- 品牌规则同步到 `apps/web/lib/brand.ts`、`docs/brand-core.md` 和 `/brand` 展示页。
- 本次不引入 AI 问答占位入口；搜索行为和提示与实际能力一致。

## 参考依据

- [W3C：Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：在窄视口下保留可阅读布局，对必须二维展示的表格使用局部滚动。
- [W3C：Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)：检查触控目标与间距；主要图标操作采用更宽裕的 44px 目标。
- [W3C：Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)：检查正常/次要文字在明暗背景下的可读性。
- [Nielsen Norman Group：Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/)：保存、上线、下线、失败与未知状态要有可理解、可行动的反馈。

这些原则用于指导此次修复，不代表本项目已获得 WCAG 认证。
