# 角色任务与内容门槛

任务卡给出 case_id、task_id、阶段、输入文件及版本摘要、允许读取范围、专属输出目录、要回答的问题、验收条件、依赖、执行者和独立审阅者。子 Agent 只提交文件及其 hash；主 Agent 登记结果。给审阅者独立上下文与可核对原始材料，不继承作者的整段自我评价。独立会话不等于不同模型或安全隔离。

## 研究员

输入：固定版本 Skill、references、脚本/评测、相关提交、Issue 线索。输出：私人证据表、关联与演变时间线、缺口、脱敏写作简报。

读取拟引用 Issue 的正文与全部可获取评论，记录分页完整性、附件缺失及不同账号的真实观点。线索匹配不等于设计关联；计划、争论、决定、实现与验证分别定位，不能将不同项目或时期拼成一次完成的交付。

主张表至少有 `claim_id、主张、来源定位、源版本/hash、关联依据、核验方式、结果时间、限制、允许公开的表述、贡献归属依据`。关联状态（确认/候选/无关联/不可访问）与主张依据（直接检查/历史报告/设计意图/推导/模拟/未证实）分开记录。

读到规则只能证明规则存在；历史报告通过不能证明当前运行有效。来源不足时返回待补，或缩小为明确标注的设计解析；不能用编造的实验或个人经历补足故事。

## 作者

输入：脱敏简报、可用主张、技术材料和限制。输出：完整文章、口播、跨两稿的主张对应表及视觉简报。

- 围绕一个问题解释条件、机制、数据/调用流、关键实现、状态变化与责任边界，不转录 Skill 或压缩为摘要。
- 交代所选方案为何成立、代价及何时改选。历史实际比较的路线与本文补充的教学比较明确区分。
- 每个关键动作包含在哪里看、看什么、预期观察、判断条件及异常后下一步；证据、权限或预算不足时可以诚实结束。
- 保留真正改变方案的失败、纠偏与验证方式；没有记录就不虚构踩坑或收益。删除不帮助读者理解的工作日志。
- 口播保留机制、取舍、关键步骤、失败分支与证据边界，使用自然短段、停顿和画面 cue。表格/代码转为讲解顺序，不逐字朗读；长内容按完整论证分集。
- 交付可复用的检查方法、模板或判断工具。字数由解释需要决定，不用长度或固定图数替代质量。

公司、品牌、人员、账号、用户、内部产品、内部域名、真实路径/编号、业务数据与组合身份线索匿名化；角色及关系前后一致。必要公开技术名可保留。检查正文、元数据、代码、图内字、alt、图注、文件名、链接和图片元数据。模拟代码/数字明确标注。无归属证据时采用讲解者视角，不能把团队贡献写成“我主导/独立实现”。

## 独立文稿审阅

阅读全文和口播，独立核查核心主张所需来源，再看操作完整性、隐私和表达。报告列出实际读取范围、未执行项、问题位置、依据、修改动作与复验方法，绑定两稿、主张表和证据快照。

`evidence`、`technical`、`privacy`、`oral` 四项均实际完成才能登记 passed。核心事实无依据、技术关系错误、贡献失实、敏感信息、关键限制缺失或标题未交付均阻断，不可用平均分抵消。证据缺口退研究员；解释缺口退作者。审阅者直接改稿后成为该稿生产者，换其他审阅者。

## 视觉制作与独立视觉审阅

制作员只接收脱敏、已通过的简报。默认仅保留解释所需的技术流程、结构图、表格与数据图，使用可核对的可编辑方式；不生成或添加装饰性/AI 概念配图，也不留下其占位、alt、图注。每张必要技术图绑定 claim_id、真实性类型、源文件及导出 hash、必要的图注/alt 和口播位置；模拟数据的标识在截取画面时仍保留。用户未来明确重新要求概念配图后才另行启动；既有私人概念图不能因文件存在而自动进入上传包。

审阅者实际打开最终导出文件，核查节点/箭头/顺序/失败出口、隐私、桌面和约 360–390px 宽度的可读性。`opened_images、semantics、privacy、desktop、mobile` 全部通过。复杂图合理拆分，不能仅缩字。图像修改后重验；语义错误回到对应研究/写作阶段。

## 合成、上传与最终验收

合成者保持已审语义，核对 Markdown 表格、代码、Mermaid、图注、alt、目录与口播 cue；新增主张返回内容审稿。包审阅的 `rendered、links、formatting、metadata` 必须实际完成。最终包审阅者回避所有受审生产者。

总控按 [台账协议](ledger.md) 调用原上传 Skill。上传成功后交完整最新 GET 与 CLI 回执；最终验收者与文稿/视觉生产者独立，逐篇检查真实后台页面和全部新图片，记录 note_id/version、桌面与移动截图或可复查观察。`desktop、mobile、images、content、private_draft` 全部通过。无图时 images 写明不适用理由后确认没有漏图。

“通过”只代表报告明确的版本及范围。文稿通过、图片字节一致、页面验收和公开发布是不同事实。总控裁决返工路线与范围，不能通过改状态把未知变成已验证。
