先说结论：Campaign 是「条件 + 动作 + 互斥策略」。前台几乎不读配置表，只消费**算完的应用结果**。但如果你不理解配置，就看不懂为什么同一购物车有时出两条折扣、有时只出一条、有时赠品入口突然消失。

---

## 1. 所有 Campaign 共用的条件

| 字段 | 含义 | 前台为什么要在意 |
|---|---|---|
| 市场 | 多市场独立配置 | 货币、免运阈值、文案都按市场 |
| Name / Description | 活动名、说明 | View Details 直接展示 |
| 有效期 | 开始 / 结束 / 立即开始 / 永不结束 | 过期要自动摘掉已应用结果 |
| 适用商品 | 整单，或 SPU/SKU/Variant/Tag/分类；可排除价格标签 | Product/Bundle 是否命中看这个 |
| 用原价计算 | 按原价算折扣 | 和现售价叠加时口径会变 |
| 适用用户 | 全员 / 邮箱名单 / 邮箱后缀 / 分群 | 未登录能过活动，过不了「指定人」 |
| User Times Limit | 每人次数 | 支付成功才计数 |
| Overall Usage Limit | 活动总次数 | 到达即等价停用 |
| 渠道 | Web / POS / 指定门店，可多选 | POS 选赠品还要库存和取货方式 |
| Zipcode | 可多选 | 换地址可能整单失去资格 |
| Unique Checker | 地址/人唯一 | 已支付成功则后续环节排除 |
| 叠加策略 | 默认 / 全互斥 / CAP / Stack | 见第 04 篇 |

Category 是后台追踪用的三层类目（Main / Sub / Sub2），可配审批人。已经生效的活动不因类目改审核设置而补审；类目下已有活动或券时，改名要二次确认，有子类目或数据时不能删。

## 2. 六种 Promo Type

### Product Discount

打在**指定商品**上，不是整单 Subtotal。

常见动作：满额/满件、分层满减、分层满折、固定减、固定折扣。可再指定「折扣落在哪些商品」——不填则等于购买条件里的商品范围。

同类可叠加的前提：**优惠 Item 不重合**。重合时同一件商品只吃力度最大的那条。

### Bundle Discount

按组合：分组 + 商品范围 + 最低购买数量。例如餐桌 1 + 餐椅 4 打 8 折。

如果一件商品同时属于两个 Bundle，不能两头都吃，只保留优惠金额更大的那个 Bundle。

### Order Discount

打在 Items Subtotal 上。可限定全部订单 / 首单 / 第 N 单 / 复购。

满 1000 减 200：Subtotal 1100 → 优惠 200 → 900，再把 200 **按售价比例摊到每个 Item**。

只有 Order Discount 能勾选 **Stack with the default priority rules**：先应用 Stack 活动，再跑默认层。

### Free Gift

满额或满件后，用户在 **Cart** 里选赠品。Address / Shipping / Payment **不能新选或改选**，要回去 Cart。

要点：

- Gift 行价格显示 Free，现售价划线；售价为 0 则只显示 Free。
- Gift 金额不进 Items Subtotal。
- 支付成功才扣赠品活动库存；整单取消要回滚。
- 多条满赠同时命中时，只允许选一条，默认创建时间近的优先。

### Free Shipping

打在运费上。触发条件之外还要求 **运费不能已经是 0**。多运单时，只摊到「实际还在收运费」的那些运单；运费模板已经免掉的那单不参与。

### Free Service

打在指定服务费种类上（例如安装、回收）。一般在 Shipping 选完服务之后才算。服务费为 0 不触发。只免勾选的那一类，按运单维度比例分摊。

## 3. 默认叠加（还没谈自定义）

同类型：

| 类型 | 同类型多条 |
|---|---|
| Product / Bundle | Item 不重合可叠加；重合取力度最大 |
| Order / Gift / Shipping / Service | 只能留 1 条，取力度最大 |

力度相同：创建时间近的优先；再相同则实现可任选（不要在面试/复盘里说「系统保证某条」）。

不同类型默认不互斥，按 `Product > Bundle > Order > Gift > Shipping > Service` 依次叠。**某一 Item 或费项剩余金额 ≤ 0，后续 Campaign 和 Coupon 都不再打它。** 可叠加额度大于剩余时，按剩余封顶。

---

## 4. 逆向

- 商品类折扣（Product / Bundle / Order）：按优惠后实付退。
- Gift / Shipping / Service：走售后规则（例如已收货不退运费）。

前台不负责算退款，但要理解「详情里看到的优惠行」和售后基数是同一套分摊结果。
