# Grafana Dashboard 配置规格

* 适用范围：`checkout` + `payment`
* 对应方案：`README.md` §8

---

## 1. 目标

定义 Grafana 侧应建立的 Dashboard 结构、指标口径与推荐图表，让团队在 5 分钟内回答：

1. 交易链路现在是否异常。
2. 异常发生在哪个步骤。
3. 是哪个 provider / region / release 受影响。
4. 是转化下降、超时上升，还是明确错误飙升。

## 2. 数据源（均由 OTel SDK 发射，见 otel-integration-spec）

| 数据类型 | 来源 | 用途 |
| --- | --- | --- |
| Metrics | Prometheus / Mimir（OTel metric → Collector） | 成功率、失败率、耗时、重试、SLO |
| Logs | Loki（pino JSON，含 `txn_trace_id` + `trace_id`） | 按 `txn_trace_id` / `order_id` / `payment_id` 回溯整笔交易（`trace_id` 钻取单 request trace） |
| Traces | Tempo（OTel trace → Collector） | Server Action → PaymentService → Provider / Backend 调用链 |
| Errors | Sentry | Root cause、stack trace、错误分桶 |

> 不使用 Datadog。客户端交易事件经 `transaction-observability` helper → OTel span/metric，不依赖 RUM action。

## 3. 通用过滤变量

所有 Dashboard 支持：`env`、`service`、`version`、`region`、`provider`、`step`、`result`。

默认值：`env=prod`、`service=joyboy-web`、`version=All`、`region=All`、`provider=All`。

## 4. Transaction Overview

### 4.1 顶部 KPI

* `create_order_success_rate` = `create_order result=success / create_order all`
* `payment_initiate_success_rate`
* `payment_capture_success_rate`
* `payment_processing_rate` = `payment_capture result=processing / all`
* `payment_timeout_rate` = `payment_capture result=timeout / all`

### 4.2 漏斗趋势

`create_order → payment_initiate → payment_capture → payment_result_render.success`，15 分钟 bucket，支持 `provider` / `region` 下钻。

### 4.3 错误分布

`payment_capture.failure by provider`、`payment_initiate.failure by provider`、`error_category by step`、`error_code top N`（来自 Loki，不是 metric label）。

### 4.4 延迟与重试

`create_order` / `payment_initiate` / `payment_capture` 的 p50 / p95；`payment_capture retry_count` 分布。

### 4.5 用户结果信号

`payment_result_render.failure` / `.processing` count、`redirect_callback_missing by provider`（= `payment_redirect` 有、`payment_callback_receive` 缺）。

**依赖埋点补齐**：`payment_result_render` 当前代码**尚未发射**（枚举已定义），见 `transaction-instrumentation-spec.md` §9。补埋前本区面板无数据；`redirect_callback_missing` 可先用 `payment_redirect` vs `payment_callback_receive` 计数差替代。

> 不使用 RUM error / rage click 作为交易核心验收指标；体验侧指标如需，另立 Web Experience milestone（可基于 OTel Browser 单独设计）。

## 5. Provider Drilldown

按 `provider` 过滤：initiate / capture request volume、success/failure/processing/timeout rate、duration p95、top error_code、top region、top version。重点图：`payment_capture failure rate by provider`、`duration p95 by provider`、`payment_callback_receive count by provider`、`payment_result_render.failure by provider`。

## 6. Release Regression

发布后 30 分钟看回归：`payment_capture_success_rate by version`、`payment_initiate_success_rate by version`、`payment_capture p95 by version`、`payment error count by version`、`Sentry issue count tagged step:payment_* by version`。

## 7. Region Health

按 `region`：`payment_capture_success_rate`、`payment_initiate_success_rate`、`timeout_rate`、`provider split`、`payment_result_render.failure`。用于判断是否单市场异常 / region-specific provider 波动 / 与 local release 相关。

## 8. 查询优先级

1. 成功率 / 错误率 → metrics（Prometheus）。
2. 交易事件详情 → structured logs（Loki，按 id）。
3. 延迟 → histogram metric 或 trace span duration。
4. root cause → 跳转 Sentry。
