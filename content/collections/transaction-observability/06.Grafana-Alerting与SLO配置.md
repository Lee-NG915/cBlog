## 1. 原则

1. 先监控成功率和超时率，不只盯 exception 数量。
2. 先覆盖 `create_order`、`payment_initiate`、`payment_capture`。
3. provider 差异大时拆 provider 级 alert。
4. Grafana 负责影响面 / 趋势 / 告警；Sentry 负责 root cause。
5. 数据来自 OTel SDK → Prometheus（指标）/ Loki（日志）。

## 2. 指标（来自 OTel，详见 transaction-instrumentation-spec §6）

| Metric | 类型 | Labels |
| --- | --- | --- |
| `transaction_step_total` | Counter | `env, service, version, domain, step, result, provider, region, error_category` |
| `transaction_step_duration_seconds` | Histogram | `env, service, version, domain, step, provider, region` |
| `transaction_retry_total` | Counter | `env, service, version, step, provider, region` |
| `transaction_callback_total` | Counter | `env, service, version, provider, region, result` |

> `order_id` / `payment_id` / `txn_trace_id` / `trace_id` 不作为 metric label（高基数），进 Loki / Tempo。

## 3. 核心 SLI / SLO（30 天窗口）

> ⚠️ 下列目标为**初始建议值**，（不同 provider 基线差异大，例如 redirect 类与 SDK 类成功率不可一刀切）。

| SLO | 分子 / 分母 | 初始目标 |
| --- | --- | --- |
| Checkout Submit Success Rate | `create_order result=success` / `create_order all` | ≥ 99.5% |
| Payment Initiate Success Rate | `payment_initiate result=success` / all | ≥ 99.0% |
| Payment Capture Success Rate | `payment_capture result=success` / all | ≥ 98.5% |
| Provider Capture Success Rate | 按 `provider` 拆 `payment_capture` | 覆盖实际活跃支付方式：`stripe-online`、`stripe-link-pay`(Express)、`grabpay`、`zippay`、`2c2p`、`paypal-online`、`affirm` |

## 4. 核心 Alert Rules（5 分钟评估，最小样本 20）

| Alert | Warning | Critical | 切分 |
| --- | --- | --- | --- |
| `create_order_failure_rate` | > 2% | — | overall |
| `payment_initiate_failure_rate` | > 3% | > 5% | overall, `provider` |
| `payment_capture_failure_rate` | > 5% | > 8% | overall, `provider`, `region` |
| `provider_timeout_spike`（15 分钟） | > 3% | — | `provider`, `region` |
| `processing_stuck_spike`（15 分钟） | 连续 > 基线 2× | — | `provider` |

## 5. PromQL 示例

### 5.1 Payment Capture Failure Rate

```plaintext
sum by (provider, region, version) (
  rate(transaction_step_total{step="payment_capture",result=~"failure|timeout"}[5m])
)
/
sum by (provider, region, version) (
  rate(transaction_step_total{step="payment_capture"}[5m])
)
```

### 5.2 Payment Capture p95

```plaintext
histogram_quantile(0.95,
  sum by (le, provider, region, version) (
    rate(transaction_step_duration_seconds_bucket{step="payment_capture"}[5m])
  )
)
```

### 5.3 Create Order Success Rate

```plaintext
sum(rate(transaction_step_total{step="create_order",result="success"}[5m]))
/
sum(rate(transaction_step_total{step="create_order"}[5m]))
```

## 6. Burn Rate Alerts（双窗口）

### 6.1 Payment Capture SLO

| 级别 | 短窗口 1h | 长窗口 6h |
| --- | --- | --- |
| Critical | > 14 | > 7 |
| Warning | > 6 | > 3 |

### 6.2 Payment Initiate SLO

| 级别 | 短窗口 1h | 长窗口 6h |
| --- | --- | --- |
| Critical | > 12 | > 6 |
| Warning | > 5 | > 2.5 |

## 7. 发布窗口加严（major release 后 30 分钟）

* `payment_capture_failure_rate > 3%`
* `payment_initiate_failure_rate > 2%`
* `payment_capture` p95 > 过去 24h 基线 × 1.5

附带 `version` / `release` / `region` / `provider`。

## 8. 告警路由

* **P1**：`payment_capture_failure_rate critical`、`Payment Capture Burn Rate critical` → payment owner + checkout owner + oncall/infra。
* **P2**：`payment_initiate_failure_rate warning`、`provider_timeout_spike` → payment owner + checkout owner。

## 9. Alert message 模板

```plaintext

env: {{ $labels.env }}
region: {{ $labels.region }}
provider: {{ $labels.provider }}
version: {{ $labels.version }}

Check:
- Dashboard: <transaction-overview-link>
- Provider Drilldown: <provider-dashboard-link>
- Logs: {service="joyboy-web", step="payment_capture", provider="{{ $labels.provider }}"}
- Trace: Tempo by trace_id
- Runbook: docs/transaction-related/transaction-observability/runbook.md
- Sentry: <sentry-search-link?query=step:payment_capture>
```
