## 1. 为什么分两半

Sentry 在本方案里只负责「为什么失败」（异常、root cause、stack trace、错误分桶）。它分两个相互独立的部分：

| 半边 | 内容 | 状态 |
| --- | --- | --- |
| **交易错误观测** | `captureTransactionError` / breadcrumb / 交易 tag / 规则采样 | ✅ 可落地，**不依赖** page 级 context；payment 主链路已在用 |
| **page 级 context 基础设施** | `setGlobalSentryContext` / `SentryContextProvider`（pageType + domain isolation scope） | ⛔ **BLOCKED**，按契约预留，迁移完成后接入 |

这样拆分的好处：OTel 接入 + 交易错误观测可以**先行落地**，不被 checkout/payment 迁移卡住；而 page 级 context 用接口契约固化下来，符合仓库现有 placeholder 风格。

## 2. 已可落地：交易错误观测

### 2.1 与现有实现对齐

* 客户端：`apps/web/instrumentation-client.ts` 的 `beforeSend` 先 `classifyErrorBucket` 写 `error_bucket` / `bucket_confidence`，再过滤噪音。
* 服务端：`apps/web/sentry.server.config.ts` 用 `classifyErrorBucketServer`。
* 业务侧统一通过 `@castlery/observability`：`captureStructuredError` / transaction helper，**禁止裸** `Sentry.captureException`（CLAUDE.md 硬规则）。

### 2.2 Scope / Tag

交易异常捕获前统一设置：`domain`、`step`、`provider`、`region`、`result`、`errorCategory`、`orderId`、`paymentId`、`traceId`（输出为 Sentry tag `txn_trace_id`）、`attemptId`、`release`。这些由 transaction helper 内部写入，业务侧不手拼 scope。

> 命名收口（方案 A）：业务伞状 ID 的 context 字段为 camelCase `traceId`，**所有出口统一** `txn_trace_id`；OTel 技术 `trace_id` 是另一条独立字段（见 §2.6）。

### 2.3 Breadcrumb（高价值节点）

`checkout page entered` · `payment method selected` · `order created` · `payment initiated` · `3DS started` · `redirect returned` · `capture succeeded`。不记录输入框级变更。

### 2.4 采样（tracesSampler）

| 范围 | 采样率 |
| --- | --- |
| 普通页面 | 0.1% ~ 1% |
| checkout / payment 页面 | ~20% |
| 失败交易 | 100% |
| 新支付方式上线窗口 | 临时 20% ~ 50% |

按路由 / `domain` / `step` / 错误状态动态决策。

### 2.5 错误分类与降级

`business_rule_error`、`user_abort`（用户取消、库存失效、coupon 失效）默认 `skipSentry`，只进日志 / metric，不进 Sentry，避免无效告警。`provider_error` / `system_error` / `timeout_error` 进 Sentry。

### 2.6 与 OTel / Grafana 的关系

Sentry 是独立通道，靠业务伞状 ID 与 Tempo / Loki / Grafana 互相定位。两层 trace 并存（方案 A）：

* **业务伞状 ID（贯穿整笔交易，前端生成）**：Sentry tag `txn_trace_id` ←→ Loki `txn_trace_id` ←→ Tempo `transaction.txn_trace_id`。前端透传 header `x-txn-trace-id`，并同时写入 Sentry tag 与日志。
* **OTel 技术 trace（per-request，后端生成）**：Loki `trace_id` ←→ Tempo 原生 trace；前端通过采集响应头 `X-Request-Id` 获得，做弱关联（见 `transaction-instrumentation-spec.md` §10.8）。
* `sentry-trace` 保留：Sentry 自有分布式追踪继续走 `sentry-trace` + `baggage`，本期不改（后端 continue 列为下一步）。
* 告警 message 附 Sentry issue search 链接（`step:payment_capture` 等），见 `grafana-alerting-slo-spec.md` §9。

## 3. BLOCKED 预留：page 级 context 基础设施

> ⛔ **不要现在落地这部分代码。** CLAUDE.md 硬规则：「Checkout / Payment / Cart 模块尚未完成兼容，兼容完成前禁止新增 Sentry instrumentation；cart route 现有 `SentryContextProvider` placeholder 不视为已完成。」本节是**迁移完成后**的接入契约。

### 3.1 契约：page.tsx

迁移完成后，每个交易 `page.tsx` 调用（即使父 layout 已有 Provider）：

```ts
// 契约示例 —— BLOCKED，迁移后接入
setGlobalSentryContext({ pageType: PAGE_TYPES.CHECKOUT, domain: BUSINESS_DOMAIN.CHECKOUT });
setGlobalSentryContext({ pageType: PAGE_TYPES.PAYMENT, domain: BUSINESS_DOMAIN.PAYMENT });
```

> `PAGE_TYPES.SEARCH` 已删除的教训同理：pageType / domain 取值以 observability 常量为准，不自造。

### 3.2 契约：layout

layout 用 `SentryContextProvider`，**不**直接调 `setGlobalSentryContext`（Provider 内部处理）。若 layout 有可能在 Provider 渲染前抛错的 `await`，则在首个 `await` 前调用 `setGlobalSentryContext`（已知例外：shop-the-look、home，**不要**外推到交易 layout）。

### 3.3 待兼容完成的接入点（占位，勿提前实现）

| 路由 | pageType | domain | 状态 |
| --- | --- | --- | --- |
| `(checkout)/checkout/page.tsx` | `CHECKOUT` | `checkout` | ⛔ blocked |
| `(checkout)/checkout/payment/page.tsx` | `PAYMENT` | `payment` | ⛔ blocked |
| `(checkout)/checkout/success/page.tsx` | `PAYMENT` | `payment` | ⛔ blocked |
| cart route | `CART` | `cart` | ⛔ blocked（现有 placeholder 待替换） |

### 3.4 解除 blocked 的前置条件

1. checkout / payment / cart 模块迁移到 joyboy 完成。
2. observability 常量（`PAGE_TYPES` / `BUSINESS_DOMAIN`）补齐交易相关取值。
3. 通过 `pnpm lint:observability`（page.tsx 必须调 `setGlobalSentryContext` 等规则）。

## 4. 边界重申（硬规则）

* **中间件 / Edge：不做 Sentry capture**，也不起 OTel tracing；`logger.*` 允许。
* **无 per-domain alert rule**：交易告警走 Grafana SLI/SLO + 失败率，不为单个 domain 新增 Sentry alert rule。
* **error-bucket.ts 是第三方域名单一事实源**：Stripe / PayPal 等支付 provider 属 `CRITICAL_THIRD_PARTY_PATTERNS`，其错误必须到达告警，不能被分类为 `third_party` 噪音。
